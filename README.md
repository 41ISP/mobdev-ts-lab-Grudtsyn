# Памятка по React

## 1. Вывод типов и явные типы

TypeScript умеет определять тип сам по значению. Явно писать тип не нужно, когда он очевиден.

```ts
const count = 0 // выведено: number
let title: string = "" // тип указан явно (лишний, но допустимый)
```

Тип нужно указывать явно:

- у параметров функций и пропсов компонентов;
- у значений, начальное значение которых ничего не говорит о будущих (пустой массив, `null`, пустая строка для состояния `Category`);
- у результата функции, если он не очевиден.

## 2. Интерфейсы (`interface`)

Интерфейс описывает форму объекта: какие у него поля и какого они типа.

```ts
export interface IPayment {
    id: string
    title: string
    amount: number
    due: string
    category: Category
    paid: boolean
}
```

Полезно знать:

- необязательное поле помечается знаком вопроса: `note?: string`;
- поле только для чтения: `readonly id: string`;
- интерфейс исчезает после компиляции, проверить значение на соответствие ему во время работы программы нельзя.

## 3. Псевдонимы типов и union-типы

Ключевое слово `type` даёт имя любому типу, а не только объекту.

```ts
export type TCategory = "video" | "apps" | "mobile" | "learning" | "other"
```

Переменной типа `Category` можно присвоить только одно из этих пяти значений. Это лучше, чем `string`:

- опечатка вроде `"vidoe"` сразу подсвечивается как ошибка;
- редактор подсказывает варианты;
- при переименовании значения TypeScript найдёт все места, которые нужно поправить.

Как выбрать между `interface` и `type`. Форму объекта обычно описывают через `interface`, объединения значений и производные типы через `type`. Главное, чтобы выбор был единым по проекту.

## 4. Утилитные типы

Готовые «функции над типами», которые строят новый тип из существующего.

**`Omit<T, K>`** убирает из типа перечисленные поля.

```ts
export type TNewPayment = Omit<IPayment, "id" | "paid">
```

_В данном приложении момент добавления ID перенесен в handler добавления подписки в стор_

Форма вводит только название, цену, дату и категорию. Поля `id` и `paid` назначает стор, поэтому в `TNewPayment` их нет. Если позже изменится `TPayment`, `TNewPayment` обновится сам.

**`Record<K, V>`** описывает объект, у которого ключи типа `K`, а значения типа `V`.

```ts
export const CATEGORY_LABELS: Record<Category, string> = {
    video: "Видео и музыка",
    apps: "Приложения",
    mobile: "Связь",
    learning: "Обучение",
    other: "Другое",
}
```

Свойство, которое нужно запомнить: если ключом служит union-тип, TypeScript требует перечислить все ключи. Добавили новую категорию в `Category`, но забыли указать её подпись, и проект не соберётся. Это защита от забытых случаев.

Другие утилиты, которые часто встречаются: `Pick<T, K>` (оставить только указанные поля), `Partial<T>` (сделать все поля необязательными), `Readonly<T>` (запретить менять поля).

## 5. Дженерики

Дженерик это тип с параметром, который записывается в угловых скобках. Параметр уточняет, с какими данными работает конструкция.

**Хук `useState`**

```ts
const [category, setCategory] = useState<Category>("video")
```

Без параметра TypeScript выведет тип `string` и позволит записать в состояние любую строку. С параметром можно записать только `Category`. Для состояний, где начальное значение однозначно определяет тип (`useState("")` для строки), параметр писать не нужно.

**Функция `create` из Zustand**

```ts
export const usePaymentsStore = create<IPaymentsState>()(
    persist(
        (set) => ({
            /* ... */
        }),
        { name: "payments", storage: createJSONStorage(() => localStorage) },
    ),
)
```

Параметр `<IPaymentsState>` задаёт тип всего стора. Благодаря этому внутри `set` и в компонентах TypeScript знает, какие поля и функции есть. Двойные скобки `()(...)` не опечатка: первые принимают тип, вторые принимают конфигурацию. Такая запись нужна, когда стор оборачивается в middleware (`persist`).

**Готовые типы-дженерики:** `Array<T>`, `Record<K, V>`, `Omit<T, K>`, `FormEvent<T>`.

## 6. Типизация функций

- Типы параметров пишутся после имён через двоеточие, тип результата пишется после списка параметров.
- Функция, которая ничего не возвращает, имеет тип результата `void`.
- Если тип результата понятен по телу стрелочной функции, его обычно не пишут.

```ts
export const formatMoney = (value: number): string => money.format(value)

export function dateParts(iso: string): { day: string; month: string } {
    /* ... */
}

interface IPaymentsState {
    items: IPayment[]
    addPayment: (data: INewPayment) => void
    removePayment: (id: string) => void
    togglePaid: (id: string) => void
}
```

В `dateParts` тип результата описан прямо в сигнатуре, это объект с двумя строковыми полями. В `IPaymentsState` описаны типы функций: список параметров, стрелка и тип результата.

## 7. Приведение типов (`as`) и утверждение `!`

Запись `значение as Тип` говорит компилятору: «поверь, здесь именно этот тип». Это не преобразование данных и не проверка. Если вы ошиблись, ошибка проявится только при работе программы.

В проекте приведение используется в трёх местах, и везде оно оправдано:

```ts
// 1. Object.keys по умолчанию возвращает string[]
export const CATEGORY_LIST = Object.keys(CATEGORY_LABELS) as Category[]

// 2. Из select приходит string, но варианты построены из CATEGORY_LIST
setCategory(e.target.value as Category)

// 3. Object.fromEntries возвращает обобщённый объект
const map = Object.fromEntries(/* ... */) as Record<Category, Row>
```

Восклицательный знак после выражения (`document.getElementById("root")!` в `main.tsx`) называется утверждением ненулевого значения. Он говорит TypeScript, что результат точно не `null`. Как и `as`, он ничего не проверяет во время работы.

Правило: приведение допустимо, когда вы точно знаете больше компилятора. Нельзя использовать его, чтобы заглушить ошибку, причину которой вы не понимаете. В таком случае сначала исправьте тип.

## Часть 2. Хранилище

### 2.1. `usePaymentsStore`: список платежей

**Что нужно сделать:**

1. Создайте файл `src/store.ts`.
2. Опишите интерфейс `IPaymentsState`: поле `items` (массив `IPayment`) и три функции: `addPayment(data: INewPayment)`, `removePayment(id: string)`, `togglePaid(id: string)`. Все три ничего не возвращают (`void`).
3. Создайте стор `usePaymentsStore` через `create`. Обратите внимание на двойные скобки: `create<IPaymentsState>()(...)`. Первые принимают тип состояния, вторые принимают конфигурацию. Так нужно, когда стор оборачивается в middleware.
4. Поле `items` изначально пустой массив.
5. `addPayment` создаёт новый объект из переданного объекта, `id` и `paid`, который равен `false` и добавляет его в конец массива. Для генерации ID используйте `nanoid`.
6. `removePayment` оставляет все платежи, кроме платежа с переданным `id` (метод `filter`).
7. `togglePaid` проходит по массиву методом `map`. У платежа с нужным `id` возвращает копию с инвертированным `paid`, остальные платежи возвращает без изменений.
8. Оберните стор в `persist`, чтобы платежи сохранялись в `localStorage` и переживали перезагрузку страницы.

**Важно:** не меняйте массив и объекты напрямую (`push`, `splice`, `p.paid = ...`). React и Zustand замечают изменения по ссылке, и компонент не перерисуется, если объект остался тем же. Всегда создавайте новый массив или новый объект.
